# T1: the smallest core

T1 is the bottom tier of the ladder in [scaling.md](scaling.md): the whole
ISA ([cpu/isa.md](../cpu/isa.md), encoding variant A) on an 8-bit datapath
and an 8-bit memory bus. The RTL is `verilog/rtl/t1_core.v` (the core) and
`t1_rf.v` (the register file). It is Verilog-2001, simulated in Icarus, and
checked against the C simulator instruction by instruction. It runs on the
Spartan-3 board at 10 MHz (fpga/README.md, `TOP=system`). How to run
everything is in
[verilog/README.md](../verilog/README.md).

**The honest summary.** The design target in scaling.md was about 7 K
transistors, like a 6502 (4.5 K) with room to spare. The RTL does not meet
it: synthesized, with the register file, it is **13.9 K transistors in nMOS
and 20.5 K in static CMOS** (13.5 K and 19.9 K without extension X). Most
of that is decoding a 16- and 32-bit ISA completely and sequencing every
instruction a byte at a time. It runs every instruction, in 2 to 7 clocks for
the common ones, and it is bus-bound: an instruction costs about one clock
for each byte it fetches plus one for each byte it loads or stores.

## Microarchitecture

**Datapath.** One 8-bit adder/logic unit and one funnel shifter (a byte of
the 16 bits `{X, Y}` shifted right 0-8) share the result byte. There are two
byte read ports and one byte write port on the register file. Everything
that is wider than a byte is a sequence of byte passes with a carry (`cy`)
or a bit (`l1`, `l2`) carried between them.

**Registers.** `t1_rf.v` is 36 bytes: r0-r15 as byte pairs, address
`2*register + byte`, so pair pN is bytes 4N to 4N+3, and four hidden bytes
(32-35) that hold the multiplier's accumulator and the temporaries of
extension X. Reads are asynchronous and the write is at the clock edge. In
silicon it is an 18 row by 16 bit RAM with a byte select; the transistor
count treats it as a macro (below).

**Addresses.** The PC (`pcf`, the next byte to fetch) and the data address
register `ar` are 21 bits. Bit 20 stands for address bits 23:20 all being
ones, so the pins carry `{4{a[20]}, a[19:0]}`: RAM at 0 up and the I/O and
boot ROM at 0xF00000 up fold onto 20 bits (the M0 fold of scaling.md). An
effective address is computed in three byte passes and the top byte is only
checked: it must be 0x00-0x0F or 0xF0-0xFF, else the core halts with FD. One
incrementer, shared by the PC and `ar`, serves both. `pcx` is a flag for the
one value the fold cannot hold: the fetch pointer stepping from 0x0FFFFF to
0x100000, where there is no memory.

**Bus.** One access per clock, byte wide: `addr`, `mem_rd`, `mem_wr` and
`dout` come from the current state, and `din` is sampled at the clock edge.
The memory is assumed to return data in the same cycle as the address (the
board's 10 ns SRAM at 50 MHz). `sr_in` supplies SR1-SR3 (the cycle and
instruction counters), which live outside the core. Nothing leaves the core
while `rst` is high.

**Sequencer.** Five states: fetch a parcel, fetch the second parcel of a
32-bit instruction, execute (a class-specific sequence of `k` steps), data
(one byte per clock at `ar`), and halted. Hardwired; decoding is a
combinational function of the two parcels (`ir`, `p2`) that also flags
reserved encodings.

**How each class is executed**, in byte passes:

| Class | Passes |
|---|---|
| ALU (ADD ... NOT, ADDI, CMPI, MOVI) | 2: low byte, then high byte with the carry; flags on the last |
| Shifts | 1 load of the count (register forms), then 2 funnel passes; left writes the high byte first, right the low byte first, so rd may be the source |
| MUL, MULH, MULHU | 16 steps (8 when the multiplier's high byte is zero) of `acc = 2 acc + (bit ? M : 0)`, each over 2 or 4 bytes, MSB first, skipping leading zero bits; the last step writes rd |
| Memory | effective address in 1-3 passes into `ar` (and pn bytes for `[pN]+`, `-[pN]`), then 1, 2 or 4 data clocks |
| Pair (ADDP*, ADDPI, MOVP, LEA, LEAPC) | 4 byte passes (fewer when a small ADDPI cannot carry out of the low byte) |
| Branch, JAL | PC + offset in 3 byte passes; B/32 and JAL first take 4 off the PC (their offset is from the instruction), and JAL saves the old PC as lr |
| JR, JALR | the 3 address bytes of pN into the PC, a clock each |

## Speedups, and what each costs

Each is a few gates and flip-flops. Transistor costs are from synthesizing
the core with the feature switched off in a scratch copy (a ±100 difference
is noise from the logic optimizer); cycle gains are from running the same
programs on both (`sim/bench/*.s`, Icarus, cycles of the whole program).

| Speedup | What it does | Cost (nMOS / CMOS transistors) | Gain |
|---|---|---|---|
| Prefetch buffer: the next instruction's first parcel is read in idle bus cycles | 16-bit buffer, 2-bit count, bus mux: ~480 / ~830 | 1.14-1.50x fewer cycles on the six programs (geometric mean 1.34x) |
| Carry stop: a branch, a small displacement or ADDPI stops after the low byte when the carry cannot change the upper bytes | compare and early exits: ~340 / ~550 | 1.02-1.16x (mean 1.10x) |
| Multiply skips leading zeros of the multiplier, and MUL uses the operand whose high byte is zero as the multiplier | ~270 / ~230 | 1.39x on arith32 (multiply-heavy), 1.00-1.02x on the rest (mean 1.06x) |
| AR tag: an access through the pair that `ar` was last loaded from, or one just written by LEA/ADDPI, with a small displacement recomputes only the low byte | 4 flip-flops, a 3-bit compare, the write snoop: ~240-540 / ~320-820 (optimizer noise) | 1.00-1.03x (mean 1.01x): poor value on these programs, the first thing to drop for size |
| *Cost of exact self-modifying code*: a store prefetches one byte, not two | 7-bit address compare, the drop, the one-byte limit: ~210 / ~310 | +4 to +7% cycles on store-heavy code against the first RTL (fib +7.4%, sieve +4.5%, memops +4.2%), none on lines or tokenize. Prefetching both bytes would need an exact compare and a two-byte rewind of the PC; not tried |

Not done, because it costs more than it saves at this size: a second
prefetch parcel, a branch target buffer, overlapping a store's data cycles
with the next instruction's fetch (one bus).

## What is and is not implemented

Implemented, and identical to fsim instruction by instruction (registers and
flags after each one, console output, how the run ends):

- The whole base ISA: all ALU, shift, multiply (MUL, MULH, MULHU), pointer,
  memory (all addressing modes, byte/word/pair), branch, JAL/JALR/JR, SYS,
  MFSR/MTSR of the flags, SYNC and NOP.
- **Extension X** (parameter `EXT_X`, default 1), as multi-cycle sequences on
  the same units. `MULPU` is the 16-step multiply writing all four bytes of
  the pair. `FSHR` and `FSHL` are the two funnel passes over a pair (the byte
  of the result that overlaps the source goes second, high first when rd is
  the upper register of the pair). `CLZ` loads rs into `ar` and shifts it
  left until the top bit is set, counting in rd, one clock per leading zero.
  `DSTEP` computes `2 pd + C - ps` in four passes into the temporaries and
  copies back either that or `2 pd + C` in four more, and sets C. With
  `EXT_X = 0` all five trap as illegal instructions (halt FE), as fsim does
  without `--ext`.
- Faults, matching fsim (`FD` here, exit code 3 there): an odd address for a
  word or pair, any access past 0x0FFFFF (stepping over it, or an address in
  0x100000-0xEFFFFF), a fetch of the next instruction after the last
  parcel of RAM (a 16-bit instruction in that last parcel executes), and a
  `reset_pc` that is odd or in that range. Reserved encodings, including an
  odd register number in a pair field, halt with `FE`, as does `SYS 0xFE`.
- A store's data is the register value before the instruction's own pointer
  write-back (`STW r4, [p2]+` with r4 in p2 stores the old r4). When the data
  register lies in the pointer pair, the data is first copied to the
  temporaries (a few extra clocks).
- Self-modifying code: a store to the next instruction is seen by it without
  `SYNC`, as in the simulator. A store prefetches at most one byte of the
  next instruction and drops it if it writes that byte. `SYNC` is a `NOP`;
  there is no I-cache to flush and no stale prefetch to flush.

Not implemented:

- Interrupts and exceptions. `RETI` halts with FF, as in the simulator.
- `MTSR` to SR1-SR3 (the counters are read-only), and SR4-SR7 (they read 0).
- Everything outside the core: memory, I/O, the cycle counters, address
  decode of 0xF00000 up (a fetch or access there reaches the pins; whether
  it is mapped is the board's decision), the clock and reset.
- Hardware divide (DSTEP, with extension X, or software), and anything the
  ISA marks as not yet defined.
- Speed on the XC3S200 (-4): on its own T1 takes 1,975 LUTs (51%) and
  meets 21 MHz; its worst path is the decode from the second parcel (24
  levels of logic). Its bus outputs settle ~40 ns after its clock edge and
  read data needs ~25 ns to reach its registers, so with the board's 10 ns
  SRAM it runs at 10 MHz in fpga/rtl/system.v. The single-cycle decode and
  same-cycle memory interface are what a faster core pipelines.

roughly 20 K cycles per second).

## Transistor count

`verilog/syn/count.py` synthesizes the core with Yosys and ABC onto two
cell libraries whose cell areas are transistors per cell (`t1_nmos.lib`:
depletion-load nMOS gates, 2-5 per gate; `t1_cmos.lib`: static CMOS, 2-8 per
gate and 20 for a flip-flop in CMOS, 8 in nMOS), sums them, and adds the
register file as a macro. The macro is 18 rows by 16 bits of static cells
with two read ports (6 + 2 transistors per bit), a decoder and byte select per
read port, and a decoder and driver for the write port: 2.8 K nMOS / 3.0 K
CMOS.

| Technology | EXT_X | core logic | register file | total |
|---|---|---|---|---|
| nMOS | 0 | 10,692 | 2,806 | 13,498 |
| nMOS | 1 | 11,067 | 2,806 | 13,873 |
| CMOS | 0 | 16,876 | 2,978 | 19,854 |
| CMOS | 1 | 17,502 | 2,978 | 20,480 |

The core before this round of changes (without extension X, the faults, the
complete decode checks or the register file) was 9,810 nMOS / 15,696 CMOS.
Core logic is 133 flip-flops (1.1 K nMOS / 2.7 K CMOS) and about 2,900 gates.
Extension X costs 0.4 K nMOS / 0.6 K CMOS; the rest of the growth is the
reserved-encoding checks, the address range checks, the saved store data and
the one-byte prefetch of stores (all things the simulator did and the first
RTL did not). Counts vary by about 2% with the optimizer's choices (the same
RTL gives a few hundred transistors' difference between runs that elaborate it
differently), so quote them to a tenth of a thousand.

The estimate in scaling.md (~7 K) counted registers at 3.5 K, ALU 0.5 K, PC
and address 0.6 K, decode 1.5 K and sequencing 1 K. The register file macro
is about right (2.8 K); decode and sequencing are roughly five times the
estimate.

## Tests

`verilog/tb/t1test.py` (directed programs, 61 runs including the programs
that must trap without extension X), `t1fuzz.py` (random register and memory
programs), `t1dec.py` (the decoder against the ISA tables on 200 K
encodings), and the assembly benchmarks in `sim/bench`, all in lockstep with
fsim; `syn/count.py --check` for latches. See verilog/README.md.
